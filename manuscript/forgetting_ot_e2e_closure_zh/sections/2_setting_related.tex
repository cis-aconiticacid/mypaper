\section{问题设定与已有系统}
\label{sec:setting-related}

\paragraph{熵正则最优传输。}
对于正的单位质量边缘分布 $a\in\R_+^n$ 和 $b\in\R_+^m$，EOT 求解
\begin{equation}
\min_{\pi\geq0}\ \langle C,\pi\rangle
+\varepsilon\sum_{ij}\pi_{ij}(\log\pi_{ij}-1),\quad
\pi\ones=a,\quad\pi^\top\ones=b.
\label{eq:eot}
\end{equation}
令 $K=\exp(-C/\varepsilon)$，Sinkhorn 交替更新对角缩放，从而形成 $\pi=\diag(u)K\diag(v)$ \citep{cuturi2013sinkhorn}。坐标方法、松弛方法、低秩方法和 Newton 方法降低单次求解内部的算术量或迭代次数 \citep{altschuler2017near,thibault2017overrelaxed,scetbon2021lowrank,kemertas2025truncated}。融合流式实现把稳定化更新改写为 LogSumExp reduction，从而降低显存流量 \citep{ye2026flashsinkhorn}。\policy{} 保留所选的内部更新，只改变下一次更新实际接收的问题集合。

\paragraph{初始化与重复 coupling。}
Carry、解析延拓和学习得到的 dual proposal 可以降低新问题的初始缺陷 \citep{amos2023meta,thornton2023initialization}。当支撑集改变时，大 coupling Flow Matching 也使用 soft $c$-transform \citep{zhang2025large}。这些机制会改变各问题所需的迭代次数。DrainSinkhorn 同时适用于两类情形：正式 Packer19 归因实验在所有实验臂中使用相同的固定 proposal，而 ImageNet-32 训练实验使用相互独立的冷启动 coupling。

\paragraph{动态批处理与批量求解器。}
自动批处理跟踪数据依赖程序中每个成员所在的程序位置 \citep{radul2020autobatching}。Orca 以一次迭代为单位调度自回归推理 \citep{yu2022orca}。在 OT 之外，Ginkgo 的 batched CG 提供了相关的执行先例：形状一致的独立线性系统按照各自的残差检验退出，融合 solver 的后续迭代会跳过已收敛系统 \citep{ginkgoBatched}。jaxipm 围绕异质迭代融合和已完成问题替换重新设计 IPOPT \citep{viljoen2026jaxipm}。在 OT 内，POT 的 \texttt{solve\_batch} 对以批量 cost matrix 表示的独立 OT 问题进行并行求解；OTT-JAX 则使用 JAX transformation 向量化多个 Sinkhorn 求解 \citep{flamary2021pot,pot2025batch,cuturi2022ott}。固定宽度的多问题 Sinkhorn 执行是本文的起点。本文处理的是此后如何移除已完成的 EOT 问题，同时保留在线成对交互，而不为每个问题实例化 cost 张量。

DrainSinkhorn 针对的是 EOT 批次的数值结构。交替缩放允许使用当前边缘进行初步检查；双边际验证器在问题输出上执行；动态压缩必须保持势函数、边缘、支撑描述符和 scratch state 之间的批元素对应关系。通用 masking 不会完成这些 EOT 专用状态变换，也不会改变宽度。\Cref{tab:prior-systems} 比较已有系统的批处理对象、完成信号和执行动作。我们的 OTT-JAX 与 PyKeOps 版本移除已完成问题，而 packed Triton 实现还使用当前边缘进行初步检查。

\paragraph{OT 消费者。}
OTT 提供广泛的 transport API \citep{cuturi2022ott}。Multisample Flow Matching 使用 OT coupling 选择训练配对 \citep{pooladian2023multisample}；这些 coupling 可以独立于网络优化提前准备 \citep{zhang2025large}。我们在工业端点上评估从 OT coupling 到下游消费者的完整路径，并让同一执行路径贯穿固定更新数的特征空间 OT-FM 训练流水线。
